  Largest: 9519 ms (L4696), 8730 ms (L3042), 8004 ms (L4025), 6820 ms, 5978 ms, 5788 ms.
- It gets worse with game time: the first 61 runs averaged 0.79 s, the last 45 runs **2.78 s** (cumulative values in the periodic
  reports at 17:24:29 and L4852).
- Shape: every run needs >= 16 iterations (sim_opt_diag.csv:275); **1,320 iterations per run on average, max 8,380**;
  139,944 iterations evaluated 590,389 records = **4.2 records per iteration** (sim_opt_diag.csv:263-265). A typical slow run is
  "records 270 -> 1": one big first iteration (longest iteration 21-413 ms), then thousands of iterations over 1-4 records.
  Cost per iteration = 172.7 s / 139,944 = **1.23 ms**, of which the parallel-for (dispatch + evaluation + help-while-waiting) is
  0.59 ms (parallel phase 82.7 s = 48 %, sim_opt_diag.csv:267, L4795). So the run time is a long tail of tiny iterations, not a large n.
- During the 8.7 s run the game still rendered 21.5 fps (L3039), so the player sees days stop, not a frozen window.

## 5. Top 10 actions (gain / risk; [M] = measured bound, [I] = estimate)

**Flip a setting (no new code)**
1. **`alloc_tracker.ini: enabled = 0`** (alloc_tracker.ini:6; its own header says "then set enabled=0 again", :2). Removes ~190-200 main-thread
   stalls of ~0.55 s, **one every 30 s, ~106-111 s per 100 min** [M], plus the mi_new/mi_free hook cost on ~12 M events [I]. Risk: none
   (diagnostic). Re-enable only for a dedicated memory run, or set `report_interval_s=0`.
2. **`fast_lookup.ini: mode = on`, `verify_every = 64`** (fast_lookup.ini:9,19). Criterion met (section 4). Gain <= ~0.25 s per save [I];
   verify with enhance's save ms (baseline avg 3,103 ms over 24 autosaves). Risk: low.
3. **`frame_pacer.ini: tick_render_hz = 30`** (MinLockTime 1 -> 33 ms; frame_pacer.ini:35). UST alone runs ~140k iterations per session of
   ~1.2 ms, each ending at RenderFrameIfNeeded (docs/re/simulation.md:105). Expected 5-15 % tick throughput (docs/re/stellaris_techniques.md:340) [I].
   Risk: choppier frames while the sim runs (10 Hz gave > 100 ms frames, frame_pacer.ini:21). A/B with tick_profiler totals.
4. **lazy_gfx two-step**: run once with `manifest_game = 1` and `prefetch_max_mb = 4096`, then `mode = on`. Bound: the init thread's
   43.5 s of texture opens in the 153.5 s load [M bound; gain I, only if prefetch makes the later open cheap]. Risk: 3.8 GB of background reads
   compete with the loader; standby-cache pressure on a machine with 6 GB free.
5. **Machine (lead)**: start the game with fewer background apps, or a fixed pagefile >= 16 GB. Other processes held ~14-15 GB commit and
   ~10 GB RAM (crash.log:2,62); RAM free fell to 475 MB in the load. Gain: fewer pagefile growths and paging stalls [I]. Risk: none.

**Needs new engine work**
6. **UST small-n path**: when the parallel-for 00e02c90 gets n <= threshold (tail iterations have 1-4 records), run the job body 00dd26e0
   inline. The body writes only its own record and seeds per record (docs/re/simulation.md:100-104 [V]), so the result is identical.
   Bound: parallel phase 82.7 s of 172.7 s [M]; realistic gain the dispatch + wait share of 1,320 tail iterations per run [I].
   First a read-only probe: which record keys survive the last 100 iterations (oscillation, possibly a mod) [I]. Risk: medium.
7. **GUI growth RE** (diag only): count anim-pool records in `M+0x88` by widget vtable (docs/re/memory.md:241) and attribute the
   `pdx_gui_factory.cpp` live sites (697 MiB). Target: the main-thread heap's +1.54 GB per 90 min [M]. Risk: none (read-only).
8. **devtools profiler for one session** (`profile=1` or Ctrl+F10) to attribute the 355 unexplained stalls (186 s) [M]. Do it with
   alloc_tracker off, or the profile is dominated by the reports. Risk: sampling overhead.
9. **HAI per-country probe**: time each range item of HAI to find the country behind 5.97 s / the 328 ms-per-tick window [M]. Enables a
   targeted fix; the only generic lever, `sim_opt throttle` of HAI (1 run in 3 skipped, ~-87 s per session [I]), changes the simulation
   (lead decision).
10. **Plugin fixes that unblock existing features**: map_cache `MC_MAX_PATHS` 8192 -> 32768 (10,024 paths seen; repeated small-texture reads
    ~16 s of the 21.5 s repeat time, mostly off the main thread [I]); par_load realdir anchor so the blend prefetch list gets native paths
    (blend step 18.7 s in the load [M], gain only if I/O-bound [I]); lazy_gfx png_cache gate to skip non-multiple-of-4 / short-mip DDS.
